# Intent MILEAGE: пробег больше 400 000 км — решение не выше `review`

## 1. Замысел

Добавить в расчёт предварительного решения по заявке проверку пробега
автомобиля: при пробеге не больше 400 000 км решение считается как раньше,
только по LTV; при пробеге больше 400 000 км автоматический `approve`
невозможен — решение не выше `review`. Правило пробега применяется поверх
решения по LTV и может только ужесточить результат, но не смягчить его. Другие
изменения в расчёт решения не входят. Источник: ответ в интервью.

## 2. Зачем

Сейчас решение по заявке зависит только от LTV, и пробег на выбор
`approve` / `review` / `reject` не влияет: заявка с любым допустимым пробегом при
низком LTV получает автоматический `approve`
(код: backend/src/Domain/DecisionEngine.php). Задача — не выдавать
автоматический `approve` заявкам с пробегом больше 400 000 км, а переводить их
в `review`. Источник: ответ в интервью.

## 3. Constraints

- Порог — **400 000 км**; это настраиваемое бизнес-число в справочнике правил,
  а не хардкод в логике. Источник: ответ в интервью.
- Граница включительно: «не больше 400 000» — пробег ровно 400 000 км проходит
  без срабатывания правила; правило срабатывает строго при пробеге
  больше 400 000 км. Источник: ответ в интервью.
- Семантика — **потолок, а не приговор**: при превышении пробега решение не
  может быть `approve` (максимум `review`), но `reject` по LTV не отменяется и
  не смягчается (порог отклонения по LTV — 85 %). Источник: ответ в интервью;
  число 85 — код: backend/config/rules.php.
- Источник пробега для правила — пробег из заявки (payload); верификация и
  сверка с другими источниками не выполняются. Источник: ответ в интервью.
- Пробег не указан или отрицателен — заявка не доходит до расчёта решения
  (существующая ошибка валидации); это поведение не меняется. Источник: код:
  backend/src/Domain/ApplicationValidator.php.
- Верхняя граница допустимого пробега при валидации ввода (сейчас 500 000 км)
  не меняется и остаётся отдельной проверкой: диапазон допустимого ввода —
  не то же самое, что порог решения. Источник: ответ в интервью; число
  500 000 — код: backend/config/rules.php.
- Существующие пороги решения по LTV и расчёт LTV не меняются. Источник:
  ответ в интервью; код: backend/config/rules.php.
- `approved_limit` при `review` по пробегу — 0, как при любом другом `review`:
  автоматический лимит при превышении порога не выдаётся. Источник: ответ
  в интервью; текущее поведение — код: backend/src/Domain/AssessmentService.php.
- Правило применяется к новым заявкам; ранее сохранённые решения
  не пересчитываются. Источник: ответ в интервью.
